# 作品集 UI 优化与验收

本轮统一为中文主界面、英文副标题。移除页面上的项目定位、MVP 能力、开发计划等批注；业务备注、诊断建议和示例数据标识保留。

## 你可以怎样判断一个页面是否需要优化

1. 先选一个任务。比如“新增职位，修改岗位，推进到面试，再刷新页面”。这条流程应能完整完成。
2. 看第一屏。产品名、主要操作和当前数据应清楚；大标题不能挤掉实际工作区。
3. 看文字。按钮用中文动词，例如“保存职位”；英文只保留产品副标题或必要术语，如 JD。
4. 看状态。空列表、搜索无结果、无效输入、删除确认、保存失败，都应该给出明确反馈。
5. 看手机。表格可在自身区域横向滚动，页面不能整体撑宽；文字和按钮不能重叠。
6. 看证据。统计要能从数据算出来，刷新不能随机改数；截图和 README 不能宣称尚未完成的功能。

反馈时可以直接用这个格式：

“在【页面】执行【操作】，当前【问题】，我期望【结果】。”

例如：“在求职工作台搜索公司后，希望只看到匹配职位；清空搜索后恢复全部职位。”

## 本轮参考与 skills

- Product UI Taste：信息层级、中文工作界面、响应式与交互状态。
- Ponytail lite：沿用现有静态 HTML 与浏览器能力，保留必要产品细节。
- [Ant Design 数据展示原则](https://ant.design/docs/spec/data-display/)：按重要性与操作频率组织内容，检查长文本和空状态。
- [Ant Design 表格](https://ant.design/components/table/)：表格适合结构化数据的扫描、比较、筛选。
- Figma 插件已经可用；本轮没有给定设计稿，因此直接修改代码并用浏览器截图验证，没有新增插件。

## 当前边界与下一步

这些仍是可交互前端原型，尚不等于完整生产项目。简历诊断使用关键词规则，没有调用大模型；运营与分析数据为示例；求职与商品数据存于当前浏览器，没有账号和云端同步。

建议优先把求职工作台做成主项目：增加职位详情、面试记录、日期提醒、JSON 导入导出，再按需要接入数据库和登录。随后补中文案例，解释用户问题、数据模型、关键决策和验证结果。

项目级验收分为五项：核心流程、UI 与可访问性、数据与错误处理、工程测试与部署、中文案例与证据。每项完成验收计 20%。本轮完成仅表示本轮列出的改动与测试，不代表五项均完成。
