# 从单页工具到产品工作区

本轮以求职管理为例。中文是主语言，英文仅为副标题，保留必要的 JD 等行业术语。

## 先想任务，再决定页面

用户一天打开产品，通常做三件事：看投递进度、处理今天的跟进、回顾哪里需要改进。
因此导航拆成“职位管理、跟进日程、求职概览”。页面数量是任务拆分的结果。

| 问题 | 本次修改 | 你可以这样判断 |
| --- | --- | --- |
| 新增表单一直占据首屏 | 新增按钮打开弹窗 | 日常查看数据时，是否有更大的工作区域 |
| 只有一张看板 | 增加列表视图，共用筛选条件 | 比较城市、薪资时，是否更容易横向对照 |
| 信息全挤在卡片里 | 卡片展示摘要，详情抽屉承载备注和面试复盘 | 第一眼能否找到公司、岗位、阶段和下一步 |
| 面试只是一种状态 | 面试有主题、时间、复盘和完成状态 | 能否记录一面、二面，以及每次要改进的问题 |
| 数字没有下一步动作 | 概览显示优先跟进，日程可完成事项 | 看到数字后，能否立即采取行动 |
| 刷新后记录可能丢失 | 本地持久化、备份、导入校验与错误反馈 | 保存失败时是否明确提示，是否保留原记录 |

## UI 审美可以这样练

1. **信息层级**：页面标题、模块标题、内容正文、辅助信息，四级即可。先用字号和留白区分，不要全部加粗。
2. **对齐与节奏**：同一排卡片的公司、岗位、金额、操作应落在相近位置。间距优先从 8、16、24、32 这些尺度选。
3. **颜色有用途**：青绿色对应主操作，蓝色对应面试数据，琥珀色提示优先级，红色提示逾期。正文保持高对比，不用浅灰承担重要信息。
4. **操作分轻重**：“新增职位”是主按钮；编辑、导出、关闭等用统一图标，并有中文标签或悬停提示。删除需要确认。
5. **逐步展开信息**：列表负责扫描，详情负责阅读，表单负责编辑。桌面详情从右侧打开；手机占满宽度。
6. **检查真实状态**：不要只检查有数据的漂亮截图。还要试没有结果、长公司名、空输入、导入错误、保存失败和键盘关闭弹窗。

这些尺度是起点，不是“套了就一定好看”。可以先选择一页，用同一组规则改完，再看整体是否更容易操作。

参考：[Ant Design 布局](https://ant.design/docs/spec/layout/)；[数据展示](https://ant.design/docs/spec/data-display/)。

## 你现在可以做一次五分钟验收

1. 打开职位管理，新增你真实想投递的岗位，填写城市、薪资和下一步动作。
2. 切换到列表，搜索公司，再按优先级排序，确认刚才的数据一致。
3. 打开详情，添加“技术一面”，填写时间和准备项。之后编辑这条记录，补充复盘。
4. 切换跟进日程，完成一条任务，再去概览看对应动态。
5. 导出备份，刷新页面，再导入同一份备份，确认职位不会重复增加。

反馈格式：“在【页面】执行【操作】，当前【问题】，我希望【结果】。”

## 面试时可以怎样介绍

用真实完成的内容描述：“我把投递、面试、跟进组织为三个工作视图。列表和看板共用数据，详情记录面试复盘。针对旧数据、重复导入和存储失败做了验证。”

当前没有真实用户规模和业务收益，因此不要写“效率提升 50%”或“服务上万用户”。可展示操作录像、测试输出、数据模型和你做取舍的原因。

## 后续增加什么才有价值

优先考虑职位附件、可配置面试阶段、可撤销删除和更完整的无障碍操作。确有多设备需求时再接账号与数据库；确有安装和通知需求时再做 PWA 或桌面客户端。每加一个功能，都需要定义数据从哪里来、操作后如何变化、失败时如何恢复。
